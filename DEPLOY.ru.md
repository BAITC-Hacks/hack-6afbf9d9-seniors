# Публикация на Render

Конфигурация готова в `render.yaml`. Аккаунт и опубликованный сайт ещё нужно создать.

1. Загрузи изменения проекта в свой GitHub-репозиторий, включая `render.yaml`, `requirements.txt` и `data/optimum.json`. Не загружай `.env` с ключами.
2. Открой https://dashboard.render.com/ и зарегистрируйся. Подключи GitHub и разреши доступ к репозиторию проекта.
3. Выбери **New → Blueprint**, затем репозиторий и ветку с изменениями.
4. Проверь конфигурацию: один Web Service `akim-city-simulator`, план **Free**. Проверь актуальные условия в интерфейсе перед созданием сервиса.
5. Создай сервис, дождись успешного развёртывания и открой выданную ссылку `https://….onrender.com`.
6. Открой `/health`: ожидается `{"status":"ok"}`. В приложении загрузи пример: стоимость 95, Score 56,54. Выполни анализ и нажми «Показать лучший план».
7. Добавь рабочую ссылку в начало `README.md`.

Если создаёшь **Web Service** вручную вместо Blueprint:

| Поле | Значение |
|---|---|
| Runtime | Python |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `python server.py --host 0.0.0.0` |
| Health Check Path | `/health` |
| Instance Type | Free — проверь доступность и условия в интерфейсе |

Сервер читает переменную `PORT`, которую задаёт платформа. Локально по умолчанию используется 8080.

Без API-ключа работают расчёт, оптимизатор и демонстрационный разбор. Для AI добавь `OPENAI_API_KEY` в **Environment** сервиса и перезапусти его. Ключ вводи только в панели хостинга; отправлять его в чат не нужно. Запросы AI могут расходовать баланс API-аккаунта.

При ошибке развёртывания посмотри первую ошибку в **Logs**. Если оптимизатор недоступен, проверь наличие `data/optimum.json` в репозитории. При изменении модели пересоздай этот файл командой из README.

Документация: [Blueprint](https://render.com/docs/blueprint-spec), [Web Services](https://render.com/docs/web-services).
